# 3–5 分钟演示脚本

## 0:00–0:35 首页与真实性边界

打开首页，指出 100 条正式记录、100 张已校验卡片图、实际生成的 2218 条 RDF triples 和 900 个数据集证据片段。强调图像是《中国传统纹样图鉴》的原创再设计，不是文物照；文化描述属于数据集自身描述，外部独立证据仍为空。

## 0:35–1:15 图鉴与结构化检索

进入“纹样图鉴与详情”，搜索“清雅”，再筛选“植物花卉纹”。打开“缠枝莲纹”详情，展示：原图、寓意、从官方详情页“常见载体”字段提取的载体、时代未知、来源与 CC BY-NC 4.0。清空或组合一个无结果条件，展示真实无结果提示。

## 1:15–1:55 知识图谱

选择“缠枝莲纹”。展示它与类别、寓意、视觉特征、应用载体和来源的实际 RDF 关系。指出没有 `hasPeriod`，因为上游没给时代；系统没有为了图好看而补边。

## 1:55–2:40 视觉星图

将聚类数设为 3，先指向“实际参与视觉分析 100 张”，再展示 PCA 星图、簇大小 55/22/23 和实际轮廓系数 0.3162077357。选择一张已有图做近邻，解释这是 RGB/HSV 颜色统计近邻，而不是文化相似。

## 2:40–4:20 设计辅助 Agent（可复现需求）

输入：

> 想设计一套宋代风格的文房茶具，希望整体简洁、雅致，寓意清雅。

运行后先展开工具调用轨迹：解析 → 搜索 → 图谱 → 证据 → 视觉 → 排序。查看 3–5 个真实候选的分项分数、匹配项、未满足项、来源和数据完整度。重点指出“历史时期=宋”必然出现在未满足项，因为正式数据时代覆盖率是 0%；匹配逻辑只查时代字段，不会从摘要误命中。证据卡标明“数据集自身描述 / 外部核验暂无”，系统建议另行标识。

可选上传一张自己的参考图，再运行并观察颜色相似分数出现；拖动三种权重说明排名是真实重算。

## 4:20–5:00 方法与限制

进入“数据与方法”，下载审计 JSON。说明 100 张图逐张通过 SHA-256；HF 第二阶段一份 JSON 对多图，导入器必须使用官方 mapping，本次因映射 CSV 网络超时未混入正式统计。结束时展示最新完整测试结果。

## 第二阶段补充：AI 纹样创作室（约 1 分钟）

从 Agent 候选卡点击“以此纹样作为创作参考”，进入创作室。确认参考记录 ID、来源和许可可见，并解释参考原图不会上传，生成提示词只引用来源可追溯的文字描述。若本机未配置 `OPENAI_API_KEY`，现场点击“生成程序化 SVG 备用图”，展示“程序化生成”标记、设计参数、参考来源与 SVG 下载；不要将该结果称为 AI 模型生成。若使用 OpenAI Images API，先说明账户计费并确认密钥已由演示者自行配置，本项目测试不调用真实付费 API。
